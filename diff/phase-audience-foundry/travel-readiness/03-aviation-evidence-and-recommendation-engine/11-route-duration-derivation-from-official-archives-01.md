+# 실제 여행 데이터 준비 계약
+
+## 목적
+
+이 문서는 `어디 갈까 ??`가 모의 비행시간 없이 실제 공공데이터만으로 여행 가능
+시간을 계산하기 위한 수집·산정·검수 경계를 고정한다. 공개 검색 요청은 계속 현재
+게시본만 읽으며 외부 source를 호출하지 않는다.
+
+## 노선별 예상 비행시간
+
+- 현재 운항 사실은 인천국제공항공사 정기운항 API가 제공한다.
+- 예상 비행시간은 해양수산부 수출입 물류 플랫폼의 공공 파일
+  `15151728`만 참고한다. 이 연간 파일을 현재 운항 사실로 표시하지 않는다.
+- worker는 공식 데이터셋 페이지에서 현재 첨부파일을 찾아 hash가 바뀐 경우에만
+  다시 해석한다. 보안문자, 로그인 또는 예상하지 못한 redirect가 나타나면 우회하지
+  않고 수집을 닫는다.
+- 원문 bytes는 메모리에서만 사용한다. DB에는 요청 receipt, 원문 hash·크기,
+  parser 결과와 정규화된 typed 값만 남긴다.
+- 2024-12-12 파일의 확인된 형식은 `ZIP → 내부 ZIP → CP949 CSV 3개`이며,
+  CSV에는 출발·도착 공항, 운항일, 계획일, 항공기 등록번호, 운항 상태와
+  `비행시간`이 있다. 숫자는 분, `시:분`은 분으로 변환하고 `0`은 미제공으로 본다.
+
+### 자동 산정 규칙 `ROUTE_DURATION_DERIVATION_V1`
+
+1. `ICN ↔ curated 13개 공항`과 `사용여부=Y`만 사용하고 출국·귀국 방향을 나눈다.
+2. 취소된 편, 0분, 해석할 수 없는 값과 30분 미만·720분 초과 값을 제외한다.
+3. 같은 방향·운항일·계획 출도착일·항공기 등록번호의 반복 관측과 코드셰어를
+   한 운항 occurrence로 묶고 그 안의 upper median을 사용한다.
+4. 방향별 occurrence가 5개 및 서로 다른 운항일 5일 미만이면 자동 산정하지 않는다.
+5. median과 MAD를 계산하고 `max(30분, 3 × 1.4826 × MAD)` 밖의 값을 제외한다.
+   표본이 8개 이상이면 IQR 결과도 계산하며 두 방법의 최종 중앙값 차이가 15분을
+   넘으면 자동 산정하지 않는다.
+6. 남은 표본이 5개 미만이거나 원표본의 70% 미만이면 자동 산정하지 않는다.
+7. 최종값은 남은 표본의 upper median이다. 출국·귀국 값과 표본·제외 건수,
+   공식 파일 기준일, source hash, parser·산정 계약 hash를 검수 증거로 남긴다.
+
+자동 산정 성공은 자동 게시 승인이 아니다. 산정 결과는 review-required 항공 후보에
+결합되고, 권한 있는 운영자가 운항표와 비행시간을 함께 승인한 뒤에만 current
+publication pointer가 이동한다.
+
+## 6개 국가 실제 source gate
+
+출시 데이터 준비 완료를 주장하기 전에 `JP`, `TW`, `HK`, `MO`, `VN`, `TH`를 같은
+실제 수집 세대에서 다음 순서로 확인한다.
+
+1. 실제 입국요건과 여행경보를 수집하고 모든 parse run이 validated인지 확인한다.
+2. 국가별 typed 사실을 공식 출처와 사람이 대조한 뒤 임시 검수 승인한다.
+3. 실제 정기운항 자료와 승인된 공식 비행시간 산정값을 항공 후보에 결합한다.
+4. disposable PostgreSQL에서 6개 국가의 entry·warning current pointer와 항공
+   pointer를 만든다.
+5. 실제 `POST /` 검색이 게시본만 읽고 국가·도시·입국요건·여행경보를 함께
+   표시하는지 확인한다.
+6. 검색 중 외부 호출, DB 쓰기, session·cookie 생성과 검색시각 저장이 없는지
+   확인하고 DB를 삭제한다.
+
+실제 운항표에 왕복편이 없거나 40시간 기준을 충족하지 못한 국가는 정상적인
+`추천 일정 없음`으로 기록한다. fetch·parse·publication 실패와 같은 결과로
+취급하지 않는다.
