# Travel Readiness 기술면접 마스터 인덱스

## 프로젝트를 한 문장으로 요약하면

공식 외부 자료를 제한된 네트워크 경계에서 수집하고, 원문 대신 해시·수집 영수증·파싱 계보·타입화된 사실을 남긴 뒤, 운영자 검토와 append-only 게시 이력을 거쳐 현재 포인터에 올리고, 사용자의 KST 여행 시간창에 맞는 왕복 기회를 요청 안에서만 계산하는 Django/PostgreSQL 애플리케이션이다.

## 조사 근거와 전체 실행 흐름

- 저장소 전체 구조, 229개 Git commit, 핵심 commit diff, Django 모델·마이그레이션의 PostgreSQL trigger SQL, 수집·파싱·게시·검색 코드, 단위·트랜잭션·브라우저·운영 테스트를 함께 조사했다.
- 주요 런타임은 Python 3.14.7, Django 5.2.17, PostgreSQL 18.6이며, 운영 프로세스는 Gunicorn을 사용한다.
- 핵심 흐름은 `SourceConfiguration/SourceRightsDecision` → `FetchAttempt` → `SourceArtifact` → `ParseRun/ParseRunInput` → 타입화된 revision → operator review/publication/audit → country 또는 flight current pointer → 요청 단위 검색이다.
- README나 설정만으로 판단하지 않고 실제 구현과 테스트를 우선했다. 같은 상태 기계가 입국 요건과 여행 경보에 반복되는 경우 대표 구현만 문제로 만들고 나머지는 연관 위치로 묶었다.
- 우선순위는 질문 가치와 10~30분 백지 구현 가치를 함께 보았다. S/A만 상세 워크북으로 확장하고, B/C는 저장소 전체를 놓치지 않기 위한 지도 역할로 남겼다.
